СТИЛЕВОЙ ГАЙД ZEROCAMS
=======================
Тёмный, «стеклянный» (glassmorphism) интерфейс: тёмно-синий фон, полупрозрачные
карточки с блюром, акцент — голубой (cyan/blue). Все стили — обычные JS-объекты
inline-style (React), никакого CSS-in-JS/Tailwind. Источник истины —
src/styles/tokens.js (экспорт `colors`, `fonts`, `orbTR/orbBL` и объект T по
умолчанию). Все страницы и компоненты берут стили оттуда, а не задают заново.


1. ЦВЕТА (src/styles/tokens.js → colors)
-----------------------------------------

colors.bg          = '#05070d'           — фон всего приложения (body/страницы).
colors.text        = '#fff'              — базовый цвет текста.
colors.accent       = 'rgb(0,170,255)'    — основной акцентный цвет (голубой).
colors.accentText   = '#9ddcff'           — акцентный текст (светлее, для читаемости на тёмном фоне).

colors.white[N] — шкала белого с прозрачностью, используется почти для всего
второстепенного текста, границ, фонов панелей. Ключи — это % прозрачности
(не всегда очевидно по названию, ориентируйтесь по значению):
  white[5]  = rgba(255,255,255,0.05)  — самый слабый фон (напр. фон карточки)
  white[6]  = rgba(255,255,255,0.06)  — разделители (divider), фон карточки
  white[8]  = rgba(255,255,255,0.08)  — границы карточек/полей/кнопок (главная граница)
  white[10] = rgba(255,255,255,0.1)
  white[15] = rgba(255,255,255,0.15)  — футер/версия (совсем бледный текст)
  white[2]  = rgba(255,255,255,0.2)   — подпись у divider
  white[3]  = rgba(255,255,255,0.3)   — второстепенные подписи (label, метаданные)
  white[4]  = rgba(255,255,255,0.4)   — приглушённый текст среднего уровня (типично: "Загрузка...", подсказки)
  white[55] = rgba(255,255,255,0.55)  — текст сообщений в диалогах (message)
  white[7]  = rgba(255,255,255,0.7)   — более заметный вторичный текст

Правило выбора: чем важнее текст — тем ближе к белому (7/55/4), чем
декоративнее / служебнее — тем прозрачнее (3/2/15).

colors.statuses.{blue|yellow|red|green|default} — «схемы» статуса, у каждой
свои bg/border/text, используются в Pill и Toggle:
  blue    → bg rgba(0,170,255,0.08)  border rgba(0,170,255,0.18)  text #9ddcff
            (роль "admin", ссылки-акценты, нейтральный статус)
  yellow  → bg rgba(255,209,102,0.08) border rgba(255,209,102,0.18) text #ffd966
            (статус "в ожидании/предупреждение", напр. invitation pending)
  red     → bg rgba(255,77,109,0.08) border rgba(255,77,109,0.18) text rgba(255,140,160,0.9)
            (ошибка, отклонено, опасное действие, offline-статус камеры)
  green   → bg rgba(0,220,130,0.08)  border rgba(0,220,130,0.18)  text rgba(100,255,200,0.9)
            (успех, "включено", "online", текущая сессия)
  default → bg white[5]  border white[10]  text white[4]-ish rgba(255,255,255,0.5)
            (нейтральный/неизвестный статус)

Как использовать: НЕ придумывайте новые оттенки на месте. Если нужен статус —
берите готовую схему colors.statuses[x] (через Pill variant или Toggle), если
нужен просто текст/фон — берите colors.white[N] по таблице выше. Новый именной
цвет — только через добавление в tokens.js, не хардкодом в компоненте.


2. ШРИФТЫ (fonts)
------------------
fonts.logo = 'Syne, sans-serif'          — только логотип/заголовок бренда (T.logo, T.logoNav).
fonts.mono = "'JetBrains Mono', monospace" — ВСЁ остальное: кнопки, поля ввода,
             pill, label, toggle, любые UI-подписи. Это основной шрифт интерфейса
             (не системный sans!). Обычный контентный текст (message в диалогах,
             email, названия камер) может идти без явного fontFamily — тогда
             используется системный sans по умолчанию браузера/страницы; но
             любой элемент управления или "техническая" подпись — mono.

Размеры (используются по месту, не вынесены в токены отдельно, но
устоявшийся паттерн по всему проекту):
  28px  — логотип (T.logo)
  20px  — логотип в навбаре (T.logoNav)
  20px  — заголовок h1 страницы ("Профиль", "Камеры" и т.п.)
  16px  — заголовок секции h2 / title в диалогах
  13-14 — обычный текст форм, кнопок, message в диалогах
  12    — вторичный текст в карточках (метаданные, даты, IP)
  11    — label над полем, pill, toggle, мелкие подписи, кнопка small
  10    — футер/версия (самый мелкий)


3. КАРТОЧКИ / ПОВЕРХНОСТИ
---------------------------
Два варианта "стекла", оба — background white[4]-ish rgba(255,255,255,0.04) +
border 1px white[8] + borderRadius 24 + backdropFilter blur(20px) + одна и та
же тень `0 20px 80px rgba(0,0,0,0.45), inset 0 1px 0 rgba(255,255,255,0.06)`.

  T.glassCard — для крупных изолированных форм (страницы login/register):
    padding 48, maxWidth 440, animation fadeIn 0.8s.
  T.dashCard  — компонент <DashCard> — для всех карточек внутри дэшборда/списков
    (камера в списке, сессия, приглашение, секция настроек):
    padding 24, animation fadeIn 0.25s (быстрее, т.к. их много и часто перерисовываются).

Правило: любая "плитка"/карточка контента внутри залогиненного интерфейса —
через <DashCard>, а не руками копировать стиль. Форма логина/регистрации —
через T.glassCard целиком (эти страницы делают это напрямую, без общего <Card>
компонента, т.к. их всего 2).

Модальные окна (ConfirmDialog, ShareLinkDialog) — это DashCard (maxWidth ~380),
поверх затемняющего фона `rgba(0,0,0,0.5)`, position fixed inset:0, flex-center,
zIndex 200 для стандартных подтверждений, zIndex 300 для диалогов, которые
могут открываться НАД другим оверлеем (напр. ShareLinkDialog над оверлеем
просмотра записи).

Фоновые "орбы" (orbTR, orbBL) — два фиксированных размытых радиальных градиента
в углах экрана (синий сверху-справа rgba(75,85,255,0.12), голубой снизу-слева
rgba(0,200,255,0.08)), рендерятся один раз в App.jsx под всем остальным
контентом (zIndex 0) — создают лёгкое ambient-свечение фона. Не дублировать на
отдельных страницах.


4. КНОПКИ (<Button>, src/components/Button.jsx)
-------------------------------------------------
Базовый стиль T.btn: фон white[6] rgba(255,255,255,0.06), border 1px white[8],
borderRadius 14, padding 14, mono-шрифт 13px, цвет #fff, transition 0.25s.

Варианты через пропсы:
  variant="default" (по умолчанию) — нейтральная кнопка (T.btn как есть).
  variant="accent"  — акцентная (главное действие): фон rgba(0,170,255,0.08),
                       border rgba(0,170,255,0.18), текст accentText (#9ddcff).
                       Использовать для "Сохранить", "Войти", подтверждающих
                       действий в диалогах.
  small             — компактная (в списках/пагинации): padding '8px 14px',
                       fontSize 11.
  disabled/loading  — opacity 0.6, cursor default; loading=true меняет текст
                       кнопки на "...".
  hover (авто)      — translateY(-2px) + тень, без доп. пропсов, срабатывает
                       на mouseenter, если кнопка не disabled.

Правило: обычные/второстепенные действия ("Отмена", "Отозвать", "Закрыть") —
default. Единственное акцентное действие на экране/диалоге — accent. Не делать
две accent-кнопки рядом.


5. ПОЛЯ ВВОДА (<InputField>, <SelectField>)
---------------------------------------------
T.input: фон white[4]-ish rgba(255,255,255,0.04), border 1px white[8],
borderRadius 14, padding '12px 16px', mono 14px, width 100%.
Фокус (T.inputFocus): border rgba(0,170,255,0.4) + внешняя тень
0 0 0 3px rgba(0,170,255,0.07) — тот же акцентный голубой, что и accent-кнопка.
Ошибка (T.inputError): border rgba(255,77,109,0.45) + тень
0 0 0 3px rgba(255,77,109,0.07) — тот же красный, что и статус "red"/errorBox.
disabled: opacity 0.6.

Label над полем (T.label): mono 11px, uppercase, letterSpacing 0.12em, цвет
white[3] rgba(255,255,255,0.3), marginBottom 8. Ошибка под полем (T.errorText):
11px, rgba(255,140,160,0.85) (тот же тон, что и red-статус text), marginTop 6.

Обёртка поля (T.fieldWrap): marginBottom 20 — стандартный вертикальный
интервал между полями формы. Не задавайте свой margin вручную, используйте
InputField/SelectField, они уже применяют fieldWrap.


6. PILL / ТЕГИ СТАТУСА (<Pill>)
----------------------------------
Универсальный компонент статус-метки. borderRadius 8, padding '4px 12px',
mono 11px, letterSpacing 0.08em. Цвет определяется пропсом
`variant` ∈ {blue, yellow, red, green, default} → берёт схему из
colors.statuses[variant] (см. раздел 2). Примеры использования по проекту:
  role пользователя (admin → blue, остальное → default)
  статус приглашения (pending → yellow, accepted → green, declined → red)
  статус камеры online/offline (green/red)
  "текущая" сессия (green)

Не красьте текст/фон статуса руками — всегда через <Pill variant=...>.


7. TOGGLE (<Toggle>)
----------------------
Переключатель "пилюля" вместо классического checkbox/switch. borderRadius 999
(полностью круглые края), fontSize 11, mono. checked → зелёная схема
(colors.statuses.green), unchecked → default (серая). Текст внутри — "●
включено" / "○ выключено" (плюс опциональный label через " — label").
Используется везде, где переключается булево состояние с явным подтверждением
через сервер (notify камеры, push-уведомления и т.п.) — не для сиюминутных UI
чекбоксов.


8. РАЗДЕЛИТЕЛИ / ТЕКСТОВЫЕ БЛОКИ
-----------------------------------
T.divider — горизонтальная линия высотой 1px, фон white[6], margin '24px 0'.
T.dividerLabel — подпись на разделителе (напр. "или"), 11px, white[2].

T.errorBox / T.successBox — блоки сообщений (не toast, а встроенные в форму):
  errorBox:   фон rgba(255,77,109,0.08), border rgba(255,77,109,0.18),
              текст rgba(255,140,160,0.9), borderRadius 12, padding '12px 16px', 12px.
  successBox: фон rgba(0,255,180,0.06), border rgba(0,255,180,0.15),
              текст rgba(100,255,200,0.9), аналогичные отступы.
Оба используют цвета, идентичные red/green статус-схемам — не изобретать новые.

T.toast — плавающие уведомления (ToastContainer): borderRadius 14, blur(20px),
тень 0 8px 32px rgba(0,0,0,0.4), maxWidth 340, padding '12px 16px', 12px.
Цвет фона тоста берётся по типу сообщения (успех/ошибка) аналогично
errorBox/successBox.


9. НАВБАР И ФУТЕР
--------------------
T.navbar: фиксированный сверху (position fixed, top/left/right 0), высота 60,
фон rgba(5,7,13,0.8) + blur(20px) (полупрозрачный тёмный, а не rgba(255..)),
border-bottom 1px white[6], flex space-between, padding '0 24px', zIndex 10
(выше orbs, ниже модалок).

T.footerVersion: центрированный мелкий текст (10px, white[15], letterSpacing
0.06em, lineHeight 1.8, padding '24px 0') — версия приложения внизу страницы.


10. ОБЩИЕ ПРАВИЛА / КАК ДОБАВЛЯТЬ НОВОЕ
-------------------------------------------
- Все новые общие константы (цвет, тень, радиус) добавлять в
  src/styles/tokens.js, а не хардкодить magic-строки в компонентах/страницах.
  Хардкод rgba(...) прямо в JSX допустим только для одноразовых мелких
  вариаций внутри уже существующего паттерна (как это уже делают Pagination
  и ConfirmDialog для мелких вспомогательных элементов), но цвет должен
  визуально соответствовать одной из палитр выше — не придумывать новый тон.
- borderRadius: 24 — крупные карточки/модалки, 14 — кнопки/поля/чипы среднего
  размера, 12 — inline-блоки сообщений (error/success box), 8 — pill, 999 —
  toggle (полностью круглый).
- Все интерактивные элементы — transition '0.25s ease' на hover/focus.
- Приоритет цвета для смыслового окраса:
    голубой (accent/blue)   — нейтральный акцент, ссылки, admin, focus
    зелёный (green)         — успех / включено / онлайн / текущее
    красный (red)           — ошибка / отключено / опасное действие / offline
    жёлтый (yellow)         — ожидание / предупреждение
    белый с прозрачностью   — всё остальное (текст, фон, границы)
- Компонуйте UI из существующих компонентов (Button, DashCard, Pill, Toggle,
  InputField, SelectField, ConfirmDialog, Pagination) — они уже реализуют все
  правила выше. Пишите новый inline-style только для layout (flex/grid/gap/
  margin) конкретного экрана, не для переизобретения цвета/тени/радиуса.
